# ArUco dictionary: regenerate and verify

The DICT_4X4_250 marker table is committed at `src/skelly-charuco/dict4x4_250_rot0.ts` and is **not** regenerated by `npm run dev` or `npm run build` — CI has no OpenCV. Regenerate it only after an OpenCV upgrade or when changing its provenance. **Regeneration is complete only when the raster verifier passes.**

The module records its source environment and marker bytes:

- `DICT_4X4_250_SOURCE_PYTHON_VERSION`
- `DICT_4X4_250_SOURCE_OPENCV_VERSION`
- `DICT_4X4_250_ROT0_BYTES` — first two rotation-0 bytes per marker id

Compare the recorded versions with your current interpreter before re-exporting.

## Regenerate only (unverified)

```bash
npm run generate:aruco-dict
```

Runs `tests/opencv-qr-test/export_dict4x4_250_ts.py`, trying interpreters in order: project `.venv` Python, `python`, Windows `py -3`, then `uv run --no-project --with-requirements tests/opencv-qr-test/requirements.txt`. The `uv` fallback uses the pinned OpenCV from `tests/opencv-qr-test/requirements.txt`; if an earlier interpreter is selected, make sure its OpenCV matches that pin. This rewrites the module and runs no verification — follow it with [Verify](#verify).

## Sync and verify (creates `.venv`)

These scripts resolve the repo root from `tests/`, run `npm install` only when `node_modules` is missing, create `.venv` with `uv` when absent, install the pinned OpenCV from `tests/opencv-qr-test/requirements.txt`, export the module, then run the raster verifier. `.venv` is left in place; the temporary `.tmp_ts_charuco_gray.bin` is always removed. They require `uv` and Node.js (npm/npx).

Windows (PowerShell 5.1+):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests\opencv-dict-sync.ps1
```

Linux / macOS / Git Bash:

```bash
chmod +x tests/opencv-dict-sync.sh   # once
./tests/opencv-dict-sync.sh
```

Success ends with the verifier's byte-for-byte `OK` line and `OK: OpenCV dict -> TypeScript export and raster check completed.`

## Manual `uv` workflow

One-shot, no venv to activate:

```bash
uv run --no-project --with-requirements tests/opencv-qr-test/requirements.txt python tests/opencv-qr-test/export_dict4x4_250_ts.py
uv run --no-project --with-requirements tests/opencv-qr-test/requirements.txt python tests/opencv-qr-test/verify_charuco_raster.py
```

Persistent `.venv` (git-ignored):

```bash
uv venv
# Windows PowerShell: .\.venv\Scripts\Activate.ps1
# Windows cmd: .venv\Scripts\activate.bat
uv pip install -r tests/opencv-qr-test/requirements.txt
python tests/opencv-qr-test/export_dict4x4_250_ts.py
python tests/opencv-qr-test/verify_charuco_raster.py
```

## Verify

```bash
npm run verify:opencv-raster
```

Alternatively, run `python tests/opencv-qr-test/verify_charuco_raster.py` in an environment whose OpenCV matches the `tests/opencv-qr-test/requirements.txt` pin. The verifier renders the board with `cv2.aruco.CharucoBoard.generateImage` and compares it byte-for-byte against `renderCharucoBoardGray` from TypeScript. Defaults: 640×480, 5×3 squares, 54 mm square, marker ratio 0.8; override with `--width`, `--height`, `--sx`, `--sy`, `--square-mm`, `--marker-ratio`. It also prints the Python/OpenCV versions recorded in the module against the current interpreter, and warns when they differ.

## Pinned OpenCV and byte parity check

`tests/opencv-qr-test/requirements.txt` is the single source of truth for the OpenCV build used by the ArUco export and checks (`opencv-contrib-python-headless==5.0.0.93`). Normal `npm run dev` / `npm run build` still needs no OpenCV; CI runs this parity check whenever `tests/opencv-qr-test/requirements.txt` changes.

`tests/verify-opencv-aruco-bytes.mjs` installs that pin with a single `uv run --no-project --with ...` invocation, extracts the DICT_4X4_250 bytes in Python, and compares all 500 rotation-0 bytes against `src/skelly-charuco/dict4x4_250_rot0.ts`. It needs `uv` on `PATH` and no npm install.

```bash
# Default: use the pin from tests/opencv-qr-test/requirements.txt
node tests/verify-opencv-aruco-bytes.mjs

# Spot-check another OpenCV version
node tests/verify-opencv-aruco-bytes.mjs --opencv-version 4.13.0.92
```

A 4-part version is a wheel version and is pinned exactly (`5.0.0.93` → `==5.0.0.93`). A 3-part version is a cv2 version and uses a PEP 440 prefix (`5.0.0` → `==5.0.0.*`). `--dict-file <path>` compares against another TS module (useful for testing mismatch handling), and `--json` prints exactly one result object on stdout while human diagnostics go to stderr.

Exit codes:

- `0` — all 500 bytes match.
- `1` — mismatch. **This is chart-spec-affecting: do not auto-regenerate.** Review the difference deliberately and bump the app major (and `CHARUCO_PRINT_LABEL_SPEC_VERSION`) per the README versioning rules. The report shows the first differing index, expected/actual bytes, the number of differing bytes, and both SHA-256 hashes.
- `2` — infrastructure or parse failure (missing `uv`, download/run failure, malformed helper output, or an unreadable/malformed dictionary module). No comparison was made.
